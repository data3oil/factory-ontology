## 一、结论先行

1. **许可不变**：继续 Apache-2.0。它带明示专利授权、允许商用与闭源再分发，与「开源算法原子层 + 闭源编排侧」的双轨边界一致；换成 MIT 会丢专利条款，换成 AGPL 会与闭源侧冲突。
2. **著作权落点改了**：原仓库只有一个空壳 Apache 模板（`LICENSE` 尾部还是 `Copyright [yyyy] [name of copyright owner]` 占位符），无任何一行写着权利人。现在把著作权人、商标条款、第三方依赖许可清单、贡献者授权（DCO）都写进 `NOTICE` / `README` / `CONTRIBUTING` / 新增 `SECURITY.md`。
3. **`LICENSE` 正文一个字都没动**：Apache-2.0 要求随分发附完整许可文本，尾部 APPENDIX 是「示例填写说明」而不是待填字段；把公司名写进 LICENSE 正文属改动标准许可文本，审计时反而多一个解释点。业界通行做法是 LICENSE 逐字保留、版权声明放 `NOTICE` + `README`，本次按此办。
4. **发现一个必须处理的真风险**：可选依赖里的 `pymupdf` 是 **AGPL-3.0**（本机安装元数据实测：`GNU AFFERO GPL 3.0`），`edge-tts` 疑为 GPL-3.0（待复核）。官方镜像不装它们，所以现在没有实际义务；但只要有人把可选依赖打进闭源交付包，就会触发 copyleft 源码开放义务。已在 `NOTICE` 明写并给部署建议。
