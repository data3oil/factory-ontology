## 一、结论（一句话版）

**一级菜单从「3 业务区 + 7 个塞在设置里的功能」改成「3 个业务入口 + 2 个建设入口 + 3 个设置入口」；
「本体编排」直接删除（不是改名）；「交付与迁移」拆掉一级身份；数据接入并入知识库与本体两条路径。**
判据不是审美，是三条对标规律：业务在前、建模在后、运维归设置；建模必须带发布语义才配一级；编排必须有执行引擎才配一级。

## 三、五个结构硬伤（按严重度）

### 硬伤 1：两个「重点能力」被降级成设置项
`数据建模 / 自助建模 / 本体演进` 三项是**建模者的主工作流**，却挂在「设置」里。对标里没有任何一家把建模放进 Settings：
Palantir 是 Workspace→Apps 里的独立应用；Stardog 是 Designer 独立应用；华为云 KG 把「本体管理」做进控制台一级。
**后果**：客户第一次登录看到的是「问答 + 看板 + 一个奇怪的交付与迁移」，会以为这是个问答工具，看不出本体是卖点。

### 硬伤 2：「数据建模」一页干了三件事
同一页里既有「上传 CSV / 连 MySQL」（数据接入），又有「建本体 / schema 校验」（结构建模），
还有「合规度导出」（治理）。对标里这三件事分属三个位置：知识库（Dify/千帆/方舟）、应用内「知识」页（Copilot Studio）、
本体管理器（Palantir）。混在一起的结果是：第一次用的人不知道该先点哪。

### 硬伤 3：「本体编排」是空壳
实测：`App.svelte:240-243` 定义 `ORCH_URL = http://<host>:8010/console`，`probeOrch()` 用 `no-cors` 探 `/health`；
`codes/api_server.py`、`codes/routes/*.py`、`web/server/index.js` **零 orch 端点**；`:8010` 当前无服务。
卡片文案自己写着「这一层是可选的能力延展」「它不在本仓库里」。
**结论：删除菜单项**（依据：对标里叫「编排」的一级菜单背后都有执行引擎——Palantir Automate 有 conditions/effects、
Databricks Lakeflow Jobs 有 job/task/trigger、dbt 有 deploy jobs；没有引擎的四家——GraphDB/Stardog/Neo4j/Cognite——都没摆这个菜单）。
真要恢复，先有「跑什么、谁触发、失败怎么办、谁有权限、运行历史在哪」，再谈菜单。

### 硬伤 4：「交付与迁移」不是终端用户的一级菜单
它的两个二级页是「版本与交付（资产快照/哈希）」「词典（lexicon 导入导出）」——这是**实施/运维动作**，
对标里同类动作落在：设置 → 系统/管理后台（MaxKB 系统设置、乐享企业管理后台、Copilot Studio Administration）。
放在业务一级里，等于把部署细节推到业务用户面前。

### 硬伤 5：界面里到处是工程词
实测界面文本出现：`kb` 代号（`seismic`）、`v3` 版本号、`:8010`、`EvolvePanel` 的「归属类」、
「深度召回（规则命中后仍跑图谱/混合/文档）」。对标产品对终端用户一律不暴露这层（Glean 只有 New chat/Search/Library/Agents）。
**商业化上这是最伤口碑的一条**：客户看到 `kb=seismic` 会问「这台机器是不是没配好」。

另加一条不算硬伤但必须处理：**「数据看板」写死了设备域**
（`DashboardPanel.svelte:39-42` 直接写「故障/异常设备」「故障率」「设备总数」「运行中」），
换到地震勘探/化工/食品库，这些指标没有意义。既然要「一个产品多行业」，看板必须由 schema 驱动。

## 四、目标信息架构（v2）

```
┌ 业务（所有角色可见）──────────────────────────────
│  问答        ← 默认落地。对话 + 证据溯源 + 结果表
│  知识库      ← 库列表 → 库详情（文档/切片/检索测试）→ 数据接入向导
│  看板        ← 域数据概览（schema 驱动，不写死设备）
├ 建设（仅管理员；默认折叠）──────────────────────────
│  本体        ← ① 建模（数据源 → 结构 → 发布） ② 图谱 ③ 演进（人确认） ④ 词典
│  评测        ← 基线 / 回归 / 命中率（对标：Copilot Studio 的 Evaluate 是独立一级）
├ 设置（底部；默认折叠）─────────────────────────────
│  模型与检索  ← 模型供应商、embedding、检索参数（原「深度召回」开关并入此处）
│  企业与成员  ← 企业信息、成员与角色、SSO
│  系统        ← 服务状态（原编排探活）、审计日志、备份与交付包、数据迁移
└──────────────────────────────────────────────
```

要点：
- **只有三个业务入口**，与对标一致（Glean：New chat/Search/Library；Dify：编排/知识库/发布）。
- **「建设」是一个分组标题，不是页面**：管理员才看到，默认折叠，避免业务用户被工程功能干扰（对标：Glean 管理端与用户导航物理分开）。
- **本体一级内部四个 tab**，其中「建模」自带三步：数据源 → 结构（草稿）→ 发布（版本+1）。这是对标结论 1 要求的「发布语义」，
  本产品已经有 `ontology_evolve` 的版本 + 快照 + 审计 + 回退，直接复用，不需要新造。
- **数据接入只有两条路径，不设独立一级**：① 进知识库（文档/表格/URL）；② 进本体（CSV/数据库→schema）。
  依据：13 个知识库产品里只有阿里云百炼把「数据接入」做成独立分组，其余全部折叠进知识库创建向导。

## 五、每页职责（做什么 / 不做什么）

| 页面 | 做什么 | **明确不做什么** | 关键元素 |
|---|---|---|---|
| 问答 | 自然语言提问、证据展示、追问、结果导出 | 不放建模入口、不显示 kb 代号 | 提问框（顶部常驻已有）、证据条、引擎/置信提示用中文人话（「规则命中」「向量+图谱混合」「模型兜底」） |
| 知识库 | 库的增删、文档上传/删除、切片查看、检索测试 | 不做 schema 编辑（那是本体） | 库卡片、上传向导、命中测试面板 |
| 看板 | 由当前本体 schema 自动生成指标卡（实体数、属性分布、异常/缺失Top） | 不写死行业指标 | 指标卡 + 一张趋势/分布图 + 「去问答」入口 |
| 本体·建模 | 选数据源 → 推断/编辑结构 → 预览 → **发布（版本+1）** | 不做文档切片（那是知识库） | 三步向导、字段语义角色、发布/回滚按钮、当前版本号 |
| 本体·图谱 | 类层次 + 实例关系浏览 | 不做查询（查询在问答） | 力导向图 + 类筛选 + 点节点看证据 |
| 本体·演进 | 候选列表 → 确认/拒绝 → 版本与快照 | 不自动并词典（已在设计里守住） | 候选卡（出现次数、建议归属类）、版本号、历史 |
| 本体·词典 | 同义词/别名/字段映射的查看与导入导出 | 不做发布（发布在建模范畴） | 词典 diff、导入校验结果 |
| 评测 | 跑基线、看命中率曲线、按题型看短板 | 不面向业务用户 | 题集、命中率、按题型拆分、历史对比 |
| 模型与检索 | 选模型（本地/云端）、embedding、检索参数 | 不在业务页出现 | 供应商卡、连通性测试、参数说明用后果语言（「更全但更慢」） |
| 企业与成员 | 企业信息、成员邀请、角色 | 不做业务配置 | 成员表、角色说明、SSO 状态 |
| 系统 | 服务状态、审计、备份/交付包、迁移 | 不做日常业务 | 健康检查、审计日志表、导出包 |

## 六、逐项去留判定

| 现状项 | 判定 | 去处 | 理由（对标/实测） |
|---|---|---|---|
| 知识问答 `query` | **保留，一级第 1 位** | 问答 | 核心功能，对标默认落地均为对话/搜索 |
| 数据看板 `dashboard` | **保留，需泛化** | 看板 | 制造客户要看概览；但必须 schema 驱动，否则换行业即废 |
| 交付与迁移（一级） | **拆解撤一级** | 系统（版本/备份/交付包）+ 本体·词典 | 实施动作不该占业务一级（MaxKB/乐享/Copilot 均在管理端） |
| 数据建模 `model` | **拆两半** | 数据接入→知识库/本体建模；建模→本体·建模 | 一页三事（硬伤 2） |
| 自助建模 `selfmodel` | **合并** | 本体·建模内的「目录扫描/自动匹配」一步 | 对标里没有独立的「自助建模」概念，属建模向导的一步 |
| 本体演进 `evolve` | **升为一级下的 tab** | 本体·演进 | 这是产品的真卖点（人在环），藏设置里等于自我否定 |
| 知识库管理 `knowledge` | **升为一级** | 知识库 | 知识库在 13 家里几乎总是一级 |
| 评测基线 `eval` | **升为一级（建设组）** | 评测 | Copilot Studio 的 Evaluate 独立一级；至少不能藏进设置 |
| **本体编排 `orch`** | **删除** | —（若保留诊断价值 → 设置·系统里一行服务状态） | 本仓库零实现、:8010 无服务；对标有引擎才配菜单 |
| 企业与账号 `enterprise` | **保留，设置内** | 设置·企业与成员 | 对标统一收进工作空间/管理端 |
| 顶部「企业设置 / 重置企业」按钮 | **保留但收进设置** | 设置·企业与成员 | 常驻按钮是运营动作，不是日常动作；重置属危险操作，要二次确认 |
| 「深度召回」开关 | **改文案 + 移位** | 设置·模型与检索 | 业务页只留「更全但更慢」的开关文案，参数进设置 |

## 七、商业化 UI 优化清单（与菜单同批做）

1. **默认落地页 = 问答**（已是），且首屏三件事：提问框、三个示例问题（取自当前库 schema）、最近一次回答。
2. **术语脱工程**：界面文本全库扫 `:8010`、`kb=`、`OWL`、`IRI`、`ttl`、`v3`、`Evolve`、`lexicon`；
   面向用户一律换成中文人话（「知识结构」「别名词典」「规则命中」）。**验收门：UI 文本 grep 上述词为 0**。
3. **空状态即引导**：没有知识库时首页不显示空表格，显示「上传第一份数据 → 生成知识结构 → 开始提问」三步。
4. **顶部条只放三样**：当前企业/知识库（中文名，不显示代号）、提问框、「设置」。退出归右上角头像菜单。
5. **控件统一**：按钮/表格/表单沿用现有 CSS 变量，不自造视觉（这是用户已强调过的硬要求）。
6. **危险操作必须二次确认**：重置企业、回滚版本、删除词典条目。
7. **看一眼就懂的状态**：版本号显示为「知识结构 v3 · 3 天前更新 · 已发布」，点开才是快照列表。
