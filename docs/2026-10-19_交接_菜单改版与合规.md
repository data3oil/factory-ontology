## 二、这一轮已经做完并实测过的

### 1. 菜单结构（P0 主体）

```
业务（所有角色）
  问答        ← 默认落地
  知识库      ← 文档上传/检索；结构化台账引导去「本体 › 数据建模」
  看板
管理（管理员；折叠）
  本体建模              ← 原「数据建模」，已与数据库接入合并为一张「接入数据」卡（两个 tab）
  自动匹配建模          ← 原「自助建模」
  本体演进（人确认）
  词典                  ← 原「交付与迁移 › 词典」
  评测
设置（折叠）
  模型与检索            ← 模型配置卡片从「数据建模」页整块搬过来（新增页面）
  企业与成员            ← 打开企业设置弹窗（沿用原有）
  系统                  ← 服务状态（原「本体编排」探活降级到这里）+ 默认落地页 + 版本与交付(AssetPanel)
```

- **「本体编排」菜单已删除**，`App.svelte` 里的 `orch` 分支、`probeOrch`、`ORCH_*` 常量、`OrchStatusCard` 引用全部移除；组件文件 `OrchStatusCard.svelte` 仍留在磁盘（未删文件，属红线），可后续清理。
- 组名从「建设」改成「管理」（用户口径：建设不符合常规）。
- **本体四项是独立菜单行**，不再藏在二级 tab 里（用户口径：不要弄没了）。点任意一项同时设置 `settingsEntry=ontology` + 对应 `activeTab`。
- 右上角「设置」按钮与左侧菜单对应：新增 `ENTRY_BY_TAB` 反查，点右侧设置会停在当前页所属条目，不再各说各话。
- 数据建模页收拢：`本地文件建模` + `数据库接入` → 一张「接入数据」卡 + 两个 tab（`intakeTab`）；`标准合规` 默认收起，只留一行分数 + 展开按钮。

### 2. 本体自演进「全部确认」

`web/src/components/EvolvePanel.svelte`：
- 新增 `bulkBusy` 状态 + `confirmAll()`：按现有 `confirm` 接口**串行**逐个确认（后端一次收一个候选），完成后给出「已确认 N 个，失败 M 个」并刷新；
- 二次确认弹窗说明「版本会逐个 +1，可回退」；
- 按钮文案「全部确认（N）」，N=待确认数量。**实测页面已渲染出「全部确认（20）」**。

### 3. 修掉的真 bug

- `evolveConfirm/evolveReject/evolveRollback` 的参数契约前后端不一致（前端传对象、api.js 按位置拆包）→ 恒 422「操作失败」。已改为整体透传 payload，并实测：字符串 name → 200；对象 name → 422。
- **诊断时的一次误写已回滚**：用一个不存在名字探接口，后端 `_ev_confirm` 不校验候选是否存在，直接并进了 seismic 词典（v1→v2）。已 rollback 回 v1 内容（现在词典版本 v3），`lexicon_seismic.json` 里已无该名字，仅 `evolve_audit.jsonl` 留痕。
- 前后端键位版本错配保护：后端还没升级时（返回旧键），`App.svelte` 的 `ENTRY_ALIASES` + `SideNav.svelte` 的 `ALIASES` 会把旧键换算成新条目，**避免整块菜单被滤空**（这是用户看到「本体建模、自演进全没了」的真因）。
